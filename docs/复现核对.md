# 淘宝用户消费数据分析（MySQL + Python 双实现）

复现和鲸项目《基于 SQL 与 PowerBI 的淘宝消费数据分析与可视化》。**Python 与 MySQL 两套实现均已在本机实跑通过，且结果逐项一致**：Python 产出 28 张结果表（`outputs/`）；MySQL 脚本在 MySQL 8.0.45 完整执行，6 张表导入行数全部正确、8 个脚本 0 错误，与 Python 结果对账全部 0 差异（见下方「双实现对账」）。

## 目录结构

```
taobao_sales_analysis/
├── data/          6 张原始 CSV（15000 订单 / 5000 用户 / 2000 商品 / 30000 行为 / 2 张特征表）
├── sql/           00~07 共 8 个 MySQL 脚本，编号对应原文档章节
```

## 快速开始

**Python（已跑通）**

```bash
# PyCharm：右键 src/main.py → Run
python src/main.py
```

依赖仅 pandas。结果打印到控制台并写入 `outputs/`。

**MySQL（已在 8.0.45 实跑验证）**

```sql
-- 先确认/开启服务端本地导入（LOAD DATA LOCAL INFILE 需要）
SHOW VARIABLES LIKE 'local_infile';       -- 若为 OFF：
SET GLOBAL local_infile = 1;              -- 需要 SUPER 权限；用完可改回 0
```

```bash
mysql --local-infile=1 -u root -p < sql/00_create_and_load.sql   # 建库建表导入，路径按实际改
mysql -u root -p taobao_sales < sql/01_data_quality.sql
mysql -u root -p taobao_sales < sql/02_cleaning.sql
mysql -u root -p taobao_sales < sql/03_dimension_model.sql
mysql -u root -p taobao_sales < sql/04_user_profile.sql
mysql -u root -p taobao_sales < sql/05_rfm.sql
mysql -u root -p taobao_sales < sql/06_product_analysis.sql
mysql -u root -p taobao_sales < sql/07_behavior_funnel.sql
```

`00` 需服务端 `local_infile=ON`；所有可空列用 `NULLIF(@col,'')` 映射，保证空字段进库为 NULL 而非 0 或空串；CSV 为 CRLF 换行，`LINES TERMINATED BY '\r\n'` 不可写成 `'\n'`。**02 的 ALTER 必须在 03 之前执行**（dim_product 引用规范化后的英文列名）。

导入精度处理（两处已按实际数据调整）：
- `avg_review_score` 用 `DECIMAL(3,2)`——CSV 中确有 4.23、4.33 这类两位小数，用 `DECIMAL(2,1)` 会被截成 4.2 / 4.3，属真实精度丢失；
- 金额列按「分」存储（`DECIMAL(x,2)`），CSV 中 `total_revenue` / `total_spent` 的 14 位小数是浮点尾巴，导入时触发 **Note 1265（截断提示，非错误）**，共 1288 条，属预期。

## 关键结论（本次实跑，数字均可在 outputs/ 查到）

- **用户画像**：30-39 岁占 44.88% 是绝对主力；女性用户 54.5%，男女客均消费接近（9090.14 vs 9404.54）；**会员等级与消费能力脱钩**（各等级均值几乎持平）；消费能力分层的客单价差异明显（低 1272.67 / 中 5900.19 / 高 20817.42）。
- **RFM**：流失用户 38.08%（人均 2377.62 元）、新用户 17.40%、重要价值用户 11.25%（人均 17041.85 元，是流失用户的 **7.2 倍**）；重要保持 + 重要挽留合计 14.69%，激活优先级最高。
- **商品**：GMV 4286.88 万，TOP3 品类占 60.9%；品牌第一小米 197.50 万；有效转化率（过滤浏览<10 后）品类间 52.23%~75.52%，而平均转化率仅 38.21%~44.79% —— **两套口径差距巨大，说明小样本虚高必须过滤**。
- **漏斗**：浏览 4988 人 → 点击 3947（79.13%）→ 收藏 2971（59.56%）→ 加购 2220（44.51%）→ 下单 4294（86.09%，口径见 D1）。

## D. 数据客观特征（复现保留原样，未修改数据）

1. **行为表时间窗 92 天，短于订单表 181 天**，且行为表没有"购买"类型。漏斗的"浏览→下单"不是同一批人在同一窗口内的连续路径，而是「全期行为用户 vs 全期下单用户」的横向对比，名义下单率因此偏高（86.09%）。这是原文档口径，非代码错误。
2. **order_date 的时刻全部落在 22:38:35 这一秒内**（17 种微秒取值，仅日期有信息量）。这正是原项目 RFM 用 `delivery_date` 而非 `order_date` 的原因，已按此实现。
3. `product_features.conversion_rate` 与 view/sales 无算术关系，不能与行为漏斗互相验证。
4. `user_features.days_since_last_order` 全为 999（常量字段，无信息量），建模时勿用。
5. users 的 province/city 存在省市不匹配（如"湖北/深圳"），地域分析按 province 汇总不受影响。
6. **79% 商品（1579/2000）浏览量 <10**，小样本过滤不是可选项。
7. 5000 用户中 257 人无任何订单，271 人订单全为取消/退款/待付款 —— RFM 实际覆盖 **4472 人**。
