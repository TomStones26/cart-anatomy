# Power BI 复现指南（手把手）

> 目标：在你的 Power BI Desktop 里复现 `bi/dashboard.html` 的 4 页看板（经营总览 / 用户分析 / RFM 分层 / 商品与漏斗）。  
> 本机环境：Power BI Desktop 2.159.883.0（商店版）、MySQL 8.0.45（服务运行中）、`taobao_sales` 库已建好并导入完毕（13 张表）。  
> 全程约 40–60 分钟。每一步都写了要点的按钮名和字段名，不需要猜。

---

## 一、先决定用哪条连接路线

Power BI 连 MySQL 有两条路，**本机的实际情况决定了选哪条**：

| 路线                       | 需要装东西                  | 本机状态                            | 结论                                |
| ------------------------ | ---------------------- | ------------------------------- | --------------------------------- |
| **ODBC**（推荐）             | 不需要                    | MySQL ODBC 9.6 Unicode 驱动**已装** | 直接能用，选这条                          |
| MySQL 连接器（Connector/NET） | 要装 MySQL Connector/NET | **未安装**                         | 想用就先去 MySQL 官网下 MSI，装完重启 Power BI |

下面按 ODBC 写。

---

## 二、连接数据（5 分钟）

### 2.1 打开 ODBC 入口

1. 打开 Power BI Desktop → 左上角 **获取数据**
2. 选 **更多…** → 左侧列表最下面 **其他** → **ODBC** → **连接**
3. 在弹出的窗口里点 **高级选项**，展开后勾选 **使用连接字符串**（不要用"数据源名称"）

### 2.2 粘贴连接字符串（**不要写用户名和密码**）

```
Driver={MySQL ODBC 9.6 Unicode Driver};Server=127.0.0.1;Port=3306;Database=taobao_sales;
```

> **关键坑**：Power BI 的 ODBC 连接器有安全策略，连接字符串里**不能出现 `UID` / `PWD`**，否则直接报  
> **「仅可使用凭据提供连接属性"uid"。」**  
> 用户名密码要留到下一步的凭据对话框里填，写进连接串一定会失败。

- 驱动名必须和 `ODBC 数据源管理器` 里显示的完全一致：`MySQL ODBC 9.6 Unicode Driver`（不是 ANSI）
- **末尾分号不能少**

### 2.3 填凭据

点 **确定** 后会弹出身份验证窗口：

1. 左侧选 **数据库**（不是"Windows"）
2. 用户名：`root`
3. 密码：你的 MySQL 密码
4. 点 **连接**

如果弹出"此连接器需要未加密的连接"，选 **确定** 继续。

### 2.3b 如果仍然连不上：改用 DSN（最稳，推荐）

连接字符串的方式受连接器版本影响较大，建一个系统 DSN 一劳永逸：

1. 开始菜单搜 **ODBC 数据源(64 位)** 并打开
2. 切到 **系统 DSN** 页 → **添加**
3. 选 **MySQL ODBC 9.6 Unicode Driver** → 完成
4. 填写：
   - TCP/IP Server：`127.0.0.1`
   - Port：`3306`
   - User：`root`
   - Password：你的密码
   - Database：下拉选 `taobao_sales`
5. 点 **Test**，出现 "Connection successful" → **OK**，Data Source Name 填 `TaobaoSales`
6. 回到 Power BI：获取数据 → ODBC → **数据源名称(DSN)** 选 `TaobaoSales` → 确定（**不要再填连接字符串**）

DSN 方式把凭据存在了系统里，Power BI 不会再要求输入，也不会报 uid 的错。

### 2.4 选表

导航器里展开 `taobao_sales`，**只勾这 6 张**（其余是中间表，不需要）：

| 表名               | 作用                    |
| ---------------- | --------------------- |
| `fact_orders`    | 订单事实表（15,000 行）       |
| `fact_behaviors` | 行为事实表（30,000 行）       |
| `dim_user`       | 用户维度（5,000 行，19 列）    |
| `dim_product`    | 商品维度（2,000 行，17 列）    |
| `rfm_segments`   | RFM 分层结果（4,472 行）     |
| `rfm_raw`        | RFM 原始 R/F/M（4,472 行） |

点 **加载**（不要点转换数据，ODBC 已经把空值处理成 NULL 了，不需要再清洗）。

> 加载慢是正常的：ODBC 走的是逐行读取，15,000 行大约 10–30 秒。如果嫌慢，用 `06` 那套 `CREATE TABLE ... AS` 的结果表也一样（已在库里）。

## 三、建模（10 分钟）

### 3.1 建关系（模型视图）

切到左侧 **模型** 图标，确认这 4 条关系（Power BI 通常会自动识别，没有就手动拖）：

| 从（多端）                        | 到（一端）                     | 基数  | 交叉筛选 |
| ---------------------------- | ------------------------- | --- | ---- |
| `fact_orders[user_id]`       | `dim_user[user_id]`       | 多对一 | 单向   |
| `fact_orders[product_id]`    | `dim_product[product_id]` | 多对一 | 单向   |
| `fact_behaviors[user_id]`    | `dim_user[user_id]`       | 多对一 | 单向   |
| `fact_behaviors[product_id]` | `dim_product[product_id]` | 多对一 | 单向   |

**注意**：`rfm_raw` / `rfm_segments` 是**独立结果表，不要和 `dim_user` 建关系**（已经建了的，在模型视图里删掉）。

原因不是"会放大行数"（它们与 dim_user 是 1:1，不会放大），而是：

1. RFM 页的所有视觉对象只用 `rfm_segments` 自身的列和度量，不需要经过 `dim_user`；
2. 一旦建了关系，你在 RFM 页放一个来自 `dim_user` 的切片器（性别、城市），筛选会顺带传递到 `rfm_segments`，"分层人数"会随切片器变化——而 R/F/M 分数是按**全量**分位数算好的静态列，筛选不会重算分数，数字容易被误读；
3. 1:1 关系在 Power BI 里本身不推荐：`rfm_segments` 4,472 行、`dim_user` 5,000 行，覆盖不全时模型会提示"缺少值"。

只有当你想「按性别/年龄看 RFM 分层分布」时才需要这条关系，那时建 `dim_user`(1) → `rfm_segments`(多)、**单向**，并记住：切片只改变人数子集，不改变分档结果。

### 3.2 建日期表

**建模** 选项卡 → **新建表**，粘贴：

```dax
日期表 =
ADDCOLUMNS (
    CALENDAR ( DATE ( 2025, 9, 1 ), DATE ( 2026, 3, 31 ) ),
    "年", YEAR ( [Date] ),
    "月", FORMAT ( [Date], "yyyy-MM" ),
    "月序", YEAR ( [Date] ) * 100 + MONTH ( [Date] )
)
```

建完后：选中 `日期表` → 右键 **标记为日期表** → 选 `Date` 列。

**再补一步排序（必做，否则折线图 X 轴会乱序）**：在表视图选中 `月` 列 → **列工具 → 按列排序 → `月序`**。

> `月` 是文本列，Power BI 对文本轴的排序并不保证按时间走；折线图一旦被设成"按度量排序"，X 轴就会按销售额从大到小重排，看起来像乱序（1 月、10 月、11 月、12 月、2 月……）。用 `月序`（202509 这种数值）当排序键，就能永远按时间顺序排。

**建关系前必须先做一件事**：给 `fact_orders` 造一个**纯日期**列，否则关系一条也匹配不上。

> 原因（已核过原始数据）：`order_date` 全部 15,000 行的时分秒都是 `22:38:35`，**没有一行是 `00:00:00`**。而 `日期表[Date]` 是整点日期，Power BI 关系按值精确匹配 → 两边永远不相等 → 全部订单掉进 `(空白)`，月度趋势图会只出一个点。详见 5.x「折线图只有一个点」。

在 `fact_orders` 新建列：

```dax
订单日期 =
DATE ( YEAR ( fact_orders[order_date] ),
       MONTH ( fact_orders[order_date] ),
       DAY ( fact_orders[order_date] ) )
```

建好后把该列数据类型设为 **日期**（不是"日期/时间"），再把 `fact_orders[订单日期]` 拖到 `日期表[Date]` 上建关系（多对一、单向）。

> 月度趋势图用 `日期表[月]` 做 X 轴，比直接用 `order_date` 更稳——不会因为某个月没数据就断档。

### 3.3 漏斗阶段排序（在 Power Query 里建排序列）

`fact_behaviors[behavior_type]` 本身就是维度（浏览/点击/收藏/加购），直接做漏斗图即可，唯一要解决的是排序。

**⚠️ 不要用 DAX 计算列做这件事**：如果建 `行为顺序 = SWITCH(behavior_type,...)` 再用它给 `behavior_type` 排序，Power BI 会报  
**「检测到循环依赖关系」**——计算列引用了该列，排序又依赖计算列。

正确做法是在 **Power Query** 里加（查询阶段的列不参与 DAX 依赖图，不会循环）：

1. **主页 → 转换数据**，打开 Power Query 编辑器
2. 选中左侧 `fact_behaviors`
3. **添加列 → 条件列**
   - 新列名：`行为顺序`
   - 如果 `behavior_type` 等于 `浏览` 则 `1`
   - 添加子句：`点击` → `2`，`收藏` → `3`，`加购` → `4`
   - 否则 `5`
4. **主页 → 关闭并应用**
5. 回到数据视图：选中 `behavior_type` 列 → **列工具 → 按列排序 → 行为顺序**

这样漏斗图的顺序固定为 浏览→点击→收藏→加购。

> 如果你之前已经在数据视图建过 DAX 版的 `行为顺序` 计算列，**先删掉它**（右键 → 删除），否则会和新列重名。

## 四、度量值（全部复制）

在 **建模 → 新建度量值**，逐个粘贴。建议先建一个空表 `_Measures` 存放（**输入数据** → 建一个只有一列的表，列名随意），这样模型视图干净。

### 4.1 经营总览用

```dax
总销售额 =
CALCULATE (
    SUM ( fact_orders[actual_payment] ),
    fact_orders[order_status] <> "已取消"
)
```

```dax
有效订单数 =
CALCULATE (
    COUNTROWS ( fact_orders ),
    fact_orders[order_status] <> "已取消"
)
```

```dax
客单价 = DIVIDE ( [总销售额], [有效订单数] )
```

```dax
下单用户数 = DISTINCTCOUNT ( fact_orders[user_id] )
```

> **口径提醒（重要，容易出错）**：这个写法统计的是**下过任何订单**的用户，包含"只下过已取消订单"的人 = **4,743**。而分子 `总销售额` 已经排除了已取消。**分子排除、分母不排除 → 人均消费被系统性拉低。**
>
> 三个口径的实际数字（已实算核实）：
>
> | 口径 | 人数 |
> | --- | ---: |
> | 下过任何订单（含只下过取消单的） | 4,743 |
> | 至少有一笔有效订单 | **4,693** |
> | 有发货记录（RFM 用的口径） | 4,472 |
>
> 要口径对齐，用下面这个版本：

```dax
有效下单用户数 =
CALCULATE (
    DISTINCTCOUNT ( fact_orders[user_id] ),
    fact_orders[order_status] <> "已取消"
)
```

```dax
人均消费 = DIVIDE ( [总销售额], [有效下单用户数] )
```

→ 4,286.88 万 ÷ 4,693 = **9,134.63 元**

> 如果你要的是"复现原项目口径"（原项目用的是 4,743 那个），保留 `下单用户数` 版本即可，人均消费 = 9,038.33。**两个都能用，但要在报告里说清用的哪个**——这类分子分母口径不一致，是数据分析里最常被追问的点。

```dax
商品数 = DISTINCTCOUNT ( dim_product[product_id] )
```

### 4.2 商品与转化用

```dax
平均转化率 = AVERAGE ( dim_product[conversion_rate] )
```

```dax
有效转化率 =
VAR t = FILTER ( dim_product, dim_product[view_count] >= 10 )
RETURN
    DIVIDE ( SUMX ( t, dim_product[total_sales] ), SUMX ( t, dim_product[view_count] ) )
```

> 这个度量放在"按品类"的表格里会自动按品类算，等价于 SQL 里 `SUM(CASE WHEN 浏览>=10 ...)`。

```dax
小样本商品占比 =
DIVIDE (
    CALCULATE ( COUNTROWS ( dim_product ), dim_product[view_count] < 10 ),
    COUNTROWS ( dim_product )
)
```

### 4.3 漏斗用

只要有 `behavior_type` 这个维度，一个度量就够了：

```dax
漏斗值 = COUNTROWS ( fact_behaviors )
```

漏斗图里：**类别** = `fact_behaviors[behavior_type]`，**值** = `漏斗值`。四个阶段自然对应 14,930 / 7,665 / 4,456 / 2,949。

要显示环比转化率，加这个度量（可选）：

```dax
环节转化率 =
VAR cur = [漏斗值]
VAR prev =
    CALCULATE (
        [漏斗值],
        OFFSET ( -1, ALLSELECTED ( fact_behaviors[behavior_type] ), ORDERBY ( fact_behaviors[行为顺序] ) )
    )
RETURN DIVIDE ( cur, prev )
```

> 如果 `OFFSET` 报错（版本较老），跳过这个度量——漏斗图本身已经能看出每一步掉多少，转化率手算即可（7665/14930=51.3%、4456/7665=58.1%、2949/4456=66.2%）。

### 4.4 RFM 用（**前提：先把两张 RFM 表合并成 `rfm_full`**）

> `rfm_segments` 只有 `user_id / r_score / f_score / m_score / user_segment`，**没有 monetary、recency、frequency**——这三个在 `rfm_raw` 里。  
> 两张表各自孤立时，既算不出"分层人均消费"，也画不了散点图。  
> 先按「六、页面 3」开头的合并步骤生成 `rfm_full`，再写下面的度量。

```dax
分层人数 = COUNTROWS ( rfm_full )
```

```dax
分层占比 = DIVIDE ( [分层人数], CALCULATE ( [分层人数], ALL ( rfm_full[user_segment] ) ) )
```

```dax
分层人均消费 = AVERAGE ( rfm_full[monetary] )
```

```dax
分层消费总额 = SUM ( rfm_full[monetary] )
```

### 4.5 格式化（可选但建议）

```dax
总销售额(万) = DIVIDE ( [总销售额], 10000 )
```

然后把度量格式设为 `0.0"万"`（度量工具 → 格式 → 自定义）。

## 五、页面 1：经营总览

画布尺寸：**文件 → 选项 → 报表设置 → 页面大小** 设为 `1280 × 720`（自定义，16:9）。

| # | 视觉对象        | 位置 (x, y)                          | 尺寸 (w, h) | 字段 / 设置                                                                  |
| - | ----------- | ---------------------------------- | --------- | ------------------------------------------------------------------------ |
| 1 | **卡片图** ×4  | (16,72) (328,72) (640,72) (952,72) | 300×100   | 分别放 `总销售额(万)`、`有效订单数`、`客单价`、`人均消费`                                       |
| 2 | **折线图**     | (16,186)                           | 736×248   | X 轴 `日期表[月]`；Y 轴 `总销售额`；打开"数据标签"                                         |
| 3 | **环形图**     | (768,186)                          | 484×248   | 图例 `fact_orders[order_status]`；值 `有效订单数`（或 `COUNTROWS(fact_orders)` 看全量） |
| 4 | **条形图**（横向） | (16,448)                           | 1236×258  | Y 轴 `dim_product[category]`；X 轴 `总销售额`；按 `总销售额` 降序                       |

**关键格式设置（让它像我的深色看板）**

- **先把卡片上"千/千万"那个后缀去掉（必做）** —— Power BI 会自动套"千/万/百万/千万"，于是出现 `4.3 千万`、`14 千` 这种显示；**数值是对的，是单位选得难看**，尤其 `有效订单数 = 13,946` 被显示成 `14 千`，精度直接丢了。

  **关键：新式卡片图（2026 版默认）的格式面板里没有"显示单位"这一项。** 在 `标注 → 值` 里只有字体、大小、颜色、透明度、对齐、将空白显示为、自动换行——**别在这儿找，找不到的**。那个后缀来自**度量值本身的"自动"数字格式**，要从度量那边改。

  **正确做法在「度量工具」里（一次改完，全报表生效）**：

  1. 在右侧数据窗格点中 `总销售额(万)` 这个**度量值**（不是卡片）
  2. 顶部功能区多出一个 **度量工具** 选项卡
  3. 这里要做**两步**，只做第一步是不够的：

  | 步骤 | 在哪 | 改成 |
  | --- | --- | --- |
  | ① 去掉"千/千万" | 度量工具 → **显示单位** 下拉（在「格式」组右边） | **无** |
  | ② 定小数位 | 度量工具 → **格式** 下拉 | 见下表 |

  > **`格式 = 整数/小数` 只控制小数位数，不控制单位。** "千/千万/百万"是「显示单位」这个独立下拉在管——所以只把格式改成"整数"，卡片上那个"千"纹丝不动，这是正常的。

  **如果功能区里找不到「显示单位」**（老版本没有这个下拉），用自定义格式字符串，效果等价且更强硬：

  度量工具 → **格式** → 选 **自定义** → 格式字符串填：

  | 度量 | 自定义格式字符串 |
  | --- | --- |
  | `总销售额(万)` | `#,0` |
  | `有效订单数` | `#,0` |
  | `客单价` | `#,0.00` |
  | `人均消费` | `#,0.00` |

  > `#,0` = 整数 + 千位分隔符；`#,0.00` = 两位小数 + 千位分隔符。自定义格式字符串会**强制覆盖**自动单位，不会再冒"千""万"。

  | 度量 | 改后显示 |
  | --- | --- |
  | `总销售额(万)` | **4,287**（标题已标"万"） |
  | `有效订单数` | **13,946** |
  | `客单价` | **3,073.91** |
  | `人均消费` | **9,134.63** |

  > 想保留一位小数就把 `总销售额(万)` 设成"小数"，显示 4,286.9。
  >
  > **另一条路（如果你更习惯在视觉对象里改）**：换成旧版视觉对象 —— 插入 → 视觉对象 → **卡片（经典）**，它才有 `标注值 → 显示单位 → 无`。新版卡片图没有这一项，这是版本差异，不是你操作错。

  > **一个容易踩的坑**：如果设好"无"之后卡片显示成 `42,868,816.33`（四千多万），说明这张卡片里装的其实是 **`总销售额`**，不是 **`总销售额(万)`**——标题可能被手动改过。把字段换成带 `(万)` 的那个，值是 `4,286.88`。

  **⚠️ 版本实测结论（2026-10 版 Power BI Desktop）**

  「度量工具」功能区里**没有**「显示单位」下拉，只有：`格式` / `货币符号 $ % ‰` / `千位分隔符 ,` / `小数位数 .00`。新版卡片图的格式面板里也没有——两头都找不到，所以那个"千"只能靠**自定义格式字符串**压掉：

  1. 选中度量 → 度量工具 → **格式 → 自定义**
  2. 格式字符串填 `#,0.0`（总销售额(万)）、`#,0`（有效订单数）、`#,0.00`（客单价 / 人均消费）
  3. 改完 **保存 → 关闭 → 重开** 一次（新版有格式缓存，不重开可能不刷新）

  **如果还是压不掉，直接用文本度量兜底（100% 可控，推荐）**：

  ```dax
  总销售额_显示 = FORMAT ( DIVIDE ( [总销售额], 10000 ), "#,0.0" ) & " 万"
  ```

  ```dax
  有效订单数_显示 = FORMAT ( [有效订单数], "#,0" )
  ```

  ```dax
  客单价_显示 = FORMAT ( [客单价], "#,0.00" ) & " 元"
  ```

  ```dax
  人均消费_显示 = FORMAT ( [人均消费], "#,0.00" ) & " 元"
  ```

### 首要嫌疑：DATE 与 DATETIME 主键对不上（本数据 100% 命中）

`日期表[Date]` 是**纯日期**（`2025-09-01 00:00:00`），而 `fact_orders[order_date]` 是**带时分秒的时间戳**。

我核过这份数据的原始值，结论非常干脆：

| 检查项 | 实测结果 |
| --- | ---: |
| `order_date` 总行数 | 15,000 |
| 其中时分秒恰好为 `00:00:00` 的行数 | **0** |
| 时分秒取值种类 | **1 种**，全部是 `22:38:35` |

也就是说**没有一条订单落在整点上**。而 Power BI 的关系是**按值精确匹配**的：`2025-09-06 00:00:00` ≠ `2025-09-06 22:38:35` → **一条也匹配不上**。全部订单被归进 `(空白)` 组，每个 `月` 都没有数据，折线上就只剩一个点。

**30 秒验证**：拖一个**表**视觉对象，行 = `日期表[月]`，值 = `有效订单数`。


3. 切到 **模型视图** → **删掉**原来 `日期表[Date]` 与 `fact_orders[order_date]` 的那条关系（点线按 Delete）
4. 把 `日期表[Date]` 拖到 `fact_orders[订单日期]` 上建关系：**多对一、单向**（`*` 在 `订单日期` 侧）
5. 回到表视觉对象复查：应变成 7 行，且与基准表逐行吻合

**查因三步（每步都能定位到唯一问题）**

1. **先看列本身对不对** —— 切到 **表视图（数据）** → 点 `日期表` → 看 `月` 列。


     ```dax
     日期表 =
     ADDCOLUMNS (
         CALENDAR ( DATE ( 2025, 9, 1 ), DATE ( 2026, 3, 31 ) ),
         "年", YEAR ( [Date] ),
         "月", FORMAT ( [Date], "yyyy-MM" ),
         "月序", YEAR ( [Date] ) * 100 + MONTH ( [Date] )
     ```

2. **再看关系通不通** —— 切到 **模型视图**，找 `日期表` 和 `fact_orders` 之间那条线。

   - 有实线但箭头朝 `日期表` → **方向反了**，双击该关系，把交叉筛选方向改成 **单一（日期表 → fact_orders）**
   - 线上的 `1` 应该在 `日期表` 侧、`*` 在 `fact_orders` 侧
   - 验证：随便放一个**表**视觉对象，行 = `日期表[月]`，值 = `有效订单数`，应该正好 7 行、数字与上表逐行吻合。**这一步不通过，折线图不可能对。**
   - 另外确认 `日期表` 已 **标记为日期表**（右键 → 标记为日期表 → 选 `Date`），否则时间智能函数不可用

3. **最后看 X 轴放的是哪个字段** —— 折线图 X 轴必须是 `日期表[月]`（字段前面的图标是**小表格**，不是日期层级 `∅`）。

   - X 轴字段后面如果带 **∑ 求和** 符号（变成"月的求和"），说明被当成数值聚合了：点字段右侧下拉 → 改成 **不汇总**。

### 折线图出来了，卡片却全变成 `--`？

`--` 在 Power BI 里表示**这个度量在当前筛选上下文里算出来是空（BLANK）**，不是"没连上"。既然折线图能出数，说明度量和事实表都没坏，问题在**卡片的上下文**。

> **先做一个推理，能直接缩小一半范围**：`总销售额` 是**求和**、`有效订单数` 是**计数**（`COUNTROWS`），两者互不依赖。如果它们**同时**为空，就不可能是某个度量写错了，只能是 `fact_orders` 在这个上下文里被**过滤成了空表**。→ 那就直奔筛选器，别在度量上找。

按下面顺序查，前两条能解决 90% 的情况：

**⓪ 先做"裸度量"测试（一次定性，不要跳过）**

新建两个**不依赖任何现有度量、不引用任何维度表**的度量值：

```dax
_测试行数 = COUNTROWS ( fact_orders )
```

```dax
_测试合计 = SUM ( fact_orders[actual_payment] )
```

新建一页（**不要放在有问题的页面上**），放两个卡片分别装这两个度量：

| --- | --- | --- |
| `_测试行数` = **15,000**、`_测试合计` = **46,165,979.95** | 事实表**没有**被过滤，模型是好的 | 走 ①～③，问题在原卡片或原度量 |
| `_测试行数` 为空或 **0** | 事实表在该上下文被**过滤成空表** | 走 ④⑤，问题在筛选器或关系 |
| 新页面正常、原页面仍空 | 原页面挂了**页面级筛选器** | 看 ④ |

**① 先测一个干净的卡片（最关键的一步）**

- 也显示 `--` → 模型层出问题了，看 ④

**② 检查卡片的字段还在不在**

点中卡片 → 右侧 **生成** 页签 → 看「字段」框里是不是空的或带红色感叹号。

**③ 检查 `总销售额(万)` 这个派生度量有没有断**

```dax
总销售额(万) = DIVIDE ( [总销售额], 10000 )
```

**④ 检查视觉级筛选器**

**⑥ 检查度量是不是重名了**

**⑦ 兜底：把度量全部重建到一个干净的表里**

1. **主页 → 输入数据** → 表名填 `_Measures`，一列 `占位`，随便填一行 → 确定
2. 在这个 `_Measures` 表下把 4.1 的 6 个度量**全部重新新建一遍**（`总销售额`、`有效订单数`、`客单价`、`下单用户数`、`人均消费`、`商品数`）
3. 把 4 张卡片**删掉重建**，字段从 `_Measures` 表里拖
4. 折线图的 Y 轴也换成 `_Measures[总销售额]`

这样所有度量都集中在唯一的表里，不会再有同名单/失效引用的可能。

## 七、页面 3：RFM 分层

### 先合并两张 RFM 表（必做，否则这一页做不出来）

`rfm_segments` 只有分层结果列（`user_id / r_score / f_score / m_score / user_segment`），`monetary / recency / frequency` 在 `rfm_raw` 里。两张表之间没有关系，所以 `AVERAGE(rfm_segments[monetary])` 必然报错——**这不是度量写错，是字段根本不在那张表里**。

解法：用 Power Query 把两张表横向拼成一张 `rfm_full`。

1. **主页 → 转换数据**
2. 左侧**右键** `rfm_segments` → **引用**（Reference）  
   → 列表底部多出一个 `rfm_segments (2)`，这是副本，原表不动
3. 选中 `rfm_segments (2)` → **主页 → 合并查询** → 下拉选 `rfm_raw` → 两表各点一下 `user_id`（选中后变绿）→ 联接种类选 **左外部** → 确定
4. 点击新列标题右侧的 **展开图标（⇔）** → **只勾** `recency`、`frequency`、`monetary` → **取消勾选**"使用原始列名作为前缀" → 确定
5. **右键** 该查询 → **重命名** → `rfm_full`
6. **主页 → 关闭并应用**

合并后 `rfm_full` 应为 **4,472 行、8 列**：`user_id, r_score, f_score, m_score, user_segment, recency, frequency, monetary`。

**行数验收（必看）**

- 4,472 行 ✅ 正确
- 5,000 行 ❌ 联接种类选成了「左外部」的反向，或第一个表选成了 `rfm_raw`
- 6,xxx 行 ❌ 联接种类选成了「完全外部」
- 只有 5 列 ❌ 第 4 步没展开，或勾错了列


> `rfm_raw`、`rfm_segments` 原表都还在（因为第 2 步用的是"引用"而不是直接改原表），它们不参与任何视觉对象，留着不影响。想干净就在 Power Query 里右键删除查询——**但删之前先把下面 4 个度量里的 `rfm_full` 改好**。

2. **图例颜色**：格式 → 标记 → 按 `user_segment` 自定义颜色（见第八节色板）。

> 散点图有 4,472 个点，拖动会卡。建议：格式 → 标记 → 大小设 4、透明度 70%。如果还是很卡，在筛选器里限定 `rfm_full[frequency] >= 2`（只保留复购用户），点数降到 **3,280**（实测值，占 4,472 的 73%——这份数据复购率很高，砍掉的不多，效果有限）。

## 十、验收：对一遍数字

做完后，逐项核对，**任何一个对不上就是口径或关系错了**：

| 指标             | 应为                             |
| -------------- | ------------------------------ |
| 总销售额           | 42,868,816.33（约 4,287 万）       |
| 有效订单数          | 13,946                         |
| 客单价            | 3,073.91                       |
| 下单用户数          | 4,743（下过任何订单）／**4,693**（至少一笔有效订单） |
| 人均消费           | 9,038.33（分母 4,743，原项目口径）／**9,134.63**（分母 4,693，口径对齐） |
| 已完成订单          | 6,085（40.57%）                  |
| TOP1 品类        | 家用电器 886 万                     |
| TOP1 品牌        | 小米 197.5 万                     |
| RFM 总人数        | 4,472                          |
| 流失用户           | 1,703（38.08%）                  |
| 重要价值用户         | 503（11.25%），人均 17,041.85       |
| 漏斗：浏览/点击/收藏/加购 | 14,930 / 7,665 / 4,456 / 2,949 |

数字对不上时，90% 是这三种原因：

1. **关系方向错了**（变成双向筛选，行数被放大）→ 检查模型视图里的箭头
2. **`已取消` 没排除** → 总销售额会变成 46,165,979.95（4,616.6 万，多出 1,054 单、329.7 万）
3. **RFM 忘了限制 `delivery_date` 非空** → 会得到 4,743 人（多出 271 位只在待付款/已取消/已退款/已付款阶段下过单的用户）

> **更正一个我先前写错的结论**（实测数据推翻了它）：
>
> - `delivery_date IS NOT NULL` 实际等价于 **「已发货 / 已收货 / 已完成」三种状态**，**不包含「已付款」**——已付款的 1,496 单全部没有发货日期（0/1496）。
> - 只用四状态列表（不加发货日期条件）= **4,605 人**、12,765 单、GMV 39,026,323.87，比 4,472 人多出 133 人。
> - **两个条件同时用（AND）** = 4,472 人。因为已付款被发货日期条件排除，四种状态里真正起作用的只有三种。
>
> 所以 DAX 里写 `NOT ISBLANK(fact_orders[delivery_date])` 得到的是 4,472 ✓；只写状态列表会得到 4,605 ✗。**结论仍是"写发货日期非空就够了"，但不是因为两者等价，而是因为状态列表里那一种被自动排除了。**
