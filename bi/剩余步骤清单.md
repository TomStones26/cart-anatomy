### 1.3 价格带结构图（后加的，目前信息量最大的一张）

**为什么加这张**：前三张图讲的是"卖了多少、什么时候卖、卖什么品类"，缺一张讲**"什么价位在赚钱"**。而这份数据的价格结构是罕见的**哑铃型**，一张图能讲完一个商业判断。

**① 先在 `dim_product` 里建价格带列**

> 数据视图 → 点中 `dim_product` → 表工具 → 新建列。序号前缀保证排序正确，不用设"按列排序"。

```dax
价格带 =
SWITCH (
    TRUE (),
    dim_product[price] < 500, "① <500元",
    dim_product[price] < 1000, "② 500-999元",
    dim_product[price] < 2000, "③ 1000-1999元",
    dim_product[price] < 3000, "④ 2000-2999元",
    dim_product[price] < 5000, "⑤ 3000-4999元",
    "⑥ ≥5000元"
)
```

**② 建图**

| 项 | 设置 |
| --- | --- |
| 类型 | 簇状柱形图（竖向） |
| X 轴 | `dim_product[价格带]` |
| Y 轴 | `总销售额` |
| 数据标签 | 打开（显示金额） |
| 工具提示 | 加 `有效订单数` |
| 位置 | `(732, 448)`，`520 × 258` |
| 标题 | 手动改成：`价格带：高价单撑起三分之一营收` |

**③ 验收**（合计 13,946 单 / 4,286.9 万）

| 价格带 | 有效订单数 | 订单占比 | 销售额 | 金额占比 |
| --- | ---: | ---: | ---: | ---: |
| ① <500 元 | 4,666 | 33.46% | 286.1 万 | 6.67% |
| ② 500-999 元 | 5,403 | 38.74% | 970.5 万 | 22.64% |
| ③ 1000-1999 元 | 1,756 | 12.59% | 604.4 万 | 14.10% |
| ④ 2000-2999 元 | **333** | **2.39%** | 187.1 万 | 4.36% |
| ⑤ 3000-4999 元 | 735 | 5.27% | 694.2 万 | 16.19% |
| ⑥ ≥5000 元 | 1,053 | **7.55%** | **1,544.6 万** | **36.03%** |

> **这张图的两个结论（可以写进报告当"洞察"）**
>
> 1. **哑铃型结构**：**订单量集中在低价**（①+② 占 72.2% 的订单），**营收集中在高价**（⑥ 只用 7.55% 的订单就贡献了 36.03% 的销售额，是 ① 的 5.4 倍）。这意味着"薄利多销"在这个品类结构里不成立，**营收对高价单高度依赖**。
> 2. **2000-2999 元是断点**：只有 333 单（2.39%），比 3000-4999 元那档还少一半。这不是需求小，而是**这个价格带几乎没有商品可选**——典型的"价格带空档"。补齐这个空档是选品上最直接的机会。

| 3 | 表 | (16,384) | 1236×340 | `dim_product[category]`、`商品数`、`浏览数`、`销量`、`平均转化率`、`有效转化率` |

**为什么条形图能替代多行卡**

- **交叉筛选照样有**：条形图和多行卡一样，点一根柱子 = 选中该品类，页面上其他视觉对象自动跟随（前提是 `fact_behaviors[product_id] → dim_product[product_id]` 这条关系在，模型里已经有了）
- **15 个长度比 30 个数字好读**：一眼看出头部和尾部，不需要逐行念数
- **商品数放工具提示**：鼠标悬停才出现，不占画面。**别把商品数和销售额做成双 Y 轴**——一个是百万级、一个是一百多，硬凑在一起两条轴都会失真

**条形图设置清单**

- [ ] X 轴 = `总销售额`，Y 轴 = `dim_product[category]`
- [ ] 排序：「…」→ 排序轴 → 排序依据 `总销售额` → **降序**
- [ ] 数据标签打开（显示金额，字号 8）
- [ ] 工具提示：把 `商品数` 拖进「工具提示」框
- [ ] Y 轴字体 8 号（15 个中文品类名，字号大了会挤）

**商品转化率**：见下方说明，三个数值都不宜直接当"转化率"写进报告。

| 指标 | 值 |
| --- | ---: |
| 浏览数合计 | 14,930 |
| 销量合计 | 15,000 |
| 平均转化率 | 40.77% |
| 有效转化率（浏览≥10 的 421 个商品） | 64.48% |
| 全量转化率（不作度量） | **100.47%** |

> **⚠️ 这三个转化率数值不合理，必须知道原因**：分子是**订单数**（15,000），分母是**浏览次数**（14,930），量纲不匹配，所以全量转化率会超过 100%。
> 这不是公式错，是原项目的数据构造决定的（一单近似对应一次浏览）。
> **处理办法二选一**：
> 1. 报告里如实标注"本数据转化率为订单数/浏览次数，非严格漏斗转化率，仅供横向比较"；
> 2. 改用漏斗口径：**加购→下单** 2,949 → 13,946。
>
> **千万别把 64% 直接写成"商品转化率"**——做过电商的人一眼就能看出问题。

## 附：这次踩过的坑（速查）

| 坑 | 症状 | 结论 |
| --- | --- | --- |
| `order_date` 全是 `22:38:35` | 日期表关系一条也匹配不上，折线图只出一个点 | 必须建**纯日期**列再建关系 |
| `月` 是文本列 | X 轴按销售额大小重排，看起来像乱序 | 设"按列排序 → 月序"，或改成自定义文本 |
| **"按列排序"在直连模式不生效** | 设了排序依旧乱 | 改用**带序号前缀的文本**（① ② ③…） |
| 改完模型后卡片显示 `--` | 视图没重算，不是模型错 | 保存 → 关闭 → 重开 |
| 新版卡片图没有"显示单位" | `4.3 千万` / `14 千` 压不掉 | 自定义格式 `#,0.0`，或 `FORMAT()` 文本度量 |
| `rfm_segments` 没有 monetary | `分层人均消费` 报错 | Power Query 合并成 `rfm_full` |
| 漏斗表未建成 | "标记无效，行 3，偏移量 21" | 不用阶段表，用 `behavior_type` + `行为顺序` 排序列 |
| **裸表达式写不进字段栏** | `COUNTROWS(dim_user)` 无处可填 | **先建成度量值**，再拖进图里 |
