# 项目总结 · 淘宝用户消费数据分析与经营看板

> 全部数据来自本项目实跑结果（MySQL 8.0 + Python 双实现，结果零差异），非行业经验值。

---

## 一、项目流程

完整覆盖电商消费者数据分析的八个核心环节，每个环节的产出都向下游交付：

| # | 环节 | 关键动作 | 交付下游的结果 |
| --- | --- | --- | --- |
| 1 | 数据质量检查 | 六张源表共 59,000 条记录，做重复、外键、缺失、异常四类体检 | 主键零重复、外键 100% 匹配、数值无越界；识别出未评分率 71.85% |
| 2 | 数据清洗与规范化 | 中文字段名英文化、空值映射为 NULL、金额精度统一、结构性缺失不填充 | 可建模的干净表，字段类型与精度已对齐 |
| 3 | 星型模型构建 | 用户、商品两维 + 订单、行为两事实 + 日期表 | 支持多维度下钻的模型底座 |
| 4 | 用户画像分析 | 性别、年龄、城市、会员等级交叉 | 主力客群画像与地域分布结论 |
| 5 | RFM 用户分层 | 分位打分 → 8 类分层 | 可执行的用户运营分组 |
| 6 | 商品分析 | 品类、品牌、价格带结构 | 品类集中度与价格带空档判断 |
| 7 | 行为漏斗分析 | 浏览 → 点击 → 收藏 → 加购四阶段 | 各环节流失定位 |
| 8 | Power BI 可视化 | 四页看板 + DAX 度量 + 交叉筛选 | 可交互的经营决策界面 |

**流程设计上的一个判断**：第 1、2 步不是走过场。未评分率 71.85% 意味着"评分"这个字段不能用来做满意度结论——如果不先体检就直接算评分均值，后面所有关于用户满意度的判断都是错的。所以质量检查的产出不只是一份报表，还是一份**字段可用性结论**。

## 二、核心分析结论

### 2.1 用户群体特征

| 维度 | 结论 | 数据 |
| --- | --- | --- |
| 年龄 | **25-44 岁为核心消费群体** | 3,792 人，占 75.84%；其中 30-39 岁 2,244 人（44.9%）为单段最高 |
| 年龄两端 | 年轻与年长客群均为长尾 | 18-24 岁 944 人（18.9%），45 岁以上 264 人（5.3%） |
| 性别 | 女性略多但差距不大 | 女 2,725（54.5%）／男 2,275（45.5%） |
| 地域 | **分布高度均匀，无明显区域集中** | 20 个城市，前 15 名每城 242–272 人，极差仅 12% |

> **地域这一条要特别说明**：条形图上前 15 个城市几乎一样长，容易被误读成图表做错了。实际是数据本身分布均匀——这意味着**地域不是这个业务的差异变量**，区域化运营的优先级应排在人货匹配之后。

### 2.2 会员等级与消费能力

| 会员等级 | 人数 | 消费额 | 人均 |
| --- | ---: | ---: | ---: |
| 铜牌会员 | 1,488（29.8%） | 1,390.5 万 | 9,344 |
| 银牌会员 | 1,291（25.8%） | 1,196.7 万 | 9,270 |
| 普通会员 | 1,190（23.8%） | 1,109.9 万 | 9,327 |
| 金牌会员 | 748（15.0%） | 664.0 万 | 8,877 |
| 钻石会员 | 283（5.7%） | 255.5 万 | 9,028 |

**结论**：金牌 + 钻石共 1,031 人（20.6%），贡献 19.92% 的消费额——**占比与贡献几乎相等，各等级人均消费都在 8,877~9,344 之间，差距不到 5%。**

**这说明会员等级与消费能力基本无关**，等级只是人数的一个映射。所以"高等级会员贡献七成 GMV"这类结论在这份数据上**不成立**，用户分层必须靠 RFM 的行为维度（近度、频度），而不能靠静态等级标签。

### 2.3 RFM 分层洞察

以 4,472 名有发货记录的用户为基数，按 R/F/M 分位打 1-5 分，组合为 8 类：

| 分层 | 人数 | 占比 | 人均消费 | 消费总额 | 运营动作 |
| --- | ---: | ---: | ---: | ---: | --- |
| 流失用户 | 1,703 | **38.08%** | 2,377.62 | 4,049,090 | 低成本触达，不投专属资源 |
| 新用户 | 778 | 17.40% | 2,652.03 | 2,063,280 | 首购后 30 天内二次转化 |
| 一般价值用户 | 629 | 14.07% | 14,190.02 | 8,925,522 | 提频，跨品类推荐 |
| **重要价值用户** | 503 | **11.25%** | **17,041.85** | 8,572,049 | VIP 专属服务，深度维护 |
| 重要保持用户 | 410 | 9.17% | 13,975.00 | 5,729,751 | 防流失预警，权益挽留 |
| 重要挽留用户 | 247 | 5.52% | 16,697.29 | 4,124,231 | **高优先级唤醒**（曾高消费、已沉默） |
| 重要发展用户 | 120 | 2.68% | 4,477.45 | 537,294 | 提客单，向上销售 |
| 一般维持用户 | 82 | 1.83% | 4,064.76 | 333,310 | 低优先级维护 |

**三层读点**：

1. **流失用户占 38.08%，却只贡献 11.8% 的消费**——这批人不是营收主力，用大额券去救性价比极低，应转给自动化触达。
2. **重要价值用户 11.25% 贡献 25% 的消费**，人均 17,041.85 元，是流失用户的 7.2 倍——真实的价值集中在这里，"VIP 深度维护"的对象应该是这一类，而不是会员等级高的那一类。
3. **重要挽留用户是全场性价比最高的目标**：247 人，人均 16,697 元，仅次于重要价值用户，但他们**已经沉默**。这是"花过钱的人走了"，唤醒成本远低于拉新。

### 2.4 商品与价格带结构

**品类集中度**：15 个品类，前 3 名（家用电器 886.2 万 / 手机数码 884.7 万 / 汽车用品 839.3 万）合计 **60.9%**，第 4 名断崖至 229.5 万，不到第 3 名的三分之一。

**价格带呈哑铃型**（合计 13,946 单 / 4,286.9 万）：

| 价格带 | 订单数 | 订单占比 | 销售额 | 金额占比 |
| --- | ---: | ---: | ---: | ---: |
| < 500 元 | 4,666 | 33.46% | 286.1 万 | 6.67% |
| 500-999 元 | 5,403 | 38.74% | 970.5 万 | 22.64% |
| 1000-1999 元 | 1,756 | 12.59% | 604.4 万 | 14.10% |
| **2000-2999 元** | **333** | **2.39%** | 187.1 万 | 4.36% |
| 3000-4999 元 | 735 | 5.27% | 694.2 万 | 16.19% |
| **≥ 5000 元** | 1,053 | **7.55%** | **1,544.6 万** | **36.03%** |

**两个可直接落地的判断**：

- **营收高度依赖高价单**：7.55% 的高价订单贡献 36.03% 销售额，是 <500 元档的 5.4 倍；而 72.2% 的订单挤在 1000 元以下，只贡献 29.31%。在这个结构里"薄利多销"不成立，**保供高价商品的库存与履约优先级，比冲订单量更直接影响营收**。
- **2000-2999 元是价格带空档**：只有 333 单，比 3000-4999 元档（735 单）还少一半。这不是需求小，而是这个价位几乎没有商品可选——**补齐该价位的 SKU 是选品上最直接的机会**。

**另一个反直觉发现**：商品数量与销售额几乎不相关。食品生鲜铺了 158 个 SKU（全场最多）只卖出 138.7 万；家用电器只有 123 个 SKU（倒数第二）却卖了 886.2 万。**铺货数量不是销售额的驱动因素，选品质量才是。**

### 2.5 转化漏斗分析

| 环节 | 行为数 | 环比转化 | 相对浏览 |
| --- | ---: | ---: | ---: |
| 浏览 | 14,930 | — | 100% |
| 点击 | 7,665 | **51.34%** | 51.34% |
| 收藏 | 4,456 | **58.13%** | 29.85% |
| 加购 | 2,949 | **66.18%** | 19.75% |

**流失定位**：从浏览量到点击，一次性流失 48.66%（7,265 条），是四个环节里绝对流失最大的一跳——**浏览层的商品曝光与主图/标题匹配度是第一优化位**；点击到收藏流失 41.87%，收藏到加购流失 33.82%，越往深处转化率越高。

**必须说明的口径问题**：本数据中"加购"行为仅 2,949 条，而有效订单有 13,946 笔——**加购行为数小于订单数，说明这不是一条真实的下单路径**（更像"一单近似对应一次浏览"的构造数据）。因此：

- 漏斗可以读**行为深度的层层衰减**，但**不能把它当成真实购买转化率**，更不能算"加购→购买"这个比率（会得到远超 100% 的荒谬结果）；
- 若要讨论购买转化，应改用"下单用户 / 浏览用户"这一口径：浏览用户 4,761 人中 4,465 人最终下单，重合度 93.8%——这一数字同样说明数据是构造的，**结论只能用于横向比较不同品类，不能用于绝对值汇报**。

## 三、技术栈

| 层 | 工具 | 具体用法 |
| --- | --- | --- |
| 数据处理 | **MySQL 8.0** | `LOAD DATA LOCAL INFILE` 批量导入；CTE + 窗口函数（`PERCENT_RANK` 分位打分、`SUM() OVER()` 占比）；8 个可复跑脚本完成从建库到漏斗的全流程 |
| 数据处理 | **Python（pandas）** | 与 SQL 并行的第二套实现，用于交叉验证；输出 28 张结果表 |
| 数据模型 | **星型模型** | `dim_user`（5,000×19）、`dim_product`（2,000×17）、`fact_orders`（15,000）、`fact_behaviors`（30,000）+ 日期表（212 行） |
| 可视化 | **Power BI** | 四页看板：经营总览、用户分析、RFM 分层、商品与漏斗；DAX 度量层集中管理口径；交叉筛选支撑品类与用户下钻 |
| 分析方法 | **RFM / 漏斗 / 画像 / 价格带** | RFM 用 `PERCENT_RANK` 分位而非等频分箱；漏斗按行为阶段递进；画像多维交叉 |

**双实现对账**：SQL 与 Python 两条独立链路按同一口径重算，RFM 有效人数、四阶段漏斗行为数、GMV、订单数、客单价、缺失分级计数共 **6 组核心指标零差异**。

## 四、口径说明

部分公开资料中的电商行业经验值在本数据集上不成立，本报告统一以实跑结果为准。若引用外部数字，建议按右列实测值校准：

| 原描述 | 本数据实测 | 处理建议 |
| --- | --- | --- |
| VIP 用户占 15%，贡献 70-80% GMV | 金牌+钻石占 **20.6%**，贡献 **19.92%**；各等级人均 8,877~9,344，差距不到 5% | 删除"贡献 70-80%"，改写成"会员等级与消费能力基本无关，分层需用 RFM" |
| 重要价值用户 15-20%；重要保持/发展/挽留 30-40% | 重要价值 **11.25%**；三类合计 **17.37%** | 按实测占比改写 |
| 浏览→点击 25-35% / 点击→收藏 40-50% / 加购→购买 50-60% | 实测 **51.34% / 58.13% / 66.18%**；且加购行为数（2,949）小于订单数（13,946），"加购→购买"无法计算 | 换成实测值，并注明"行为数口径，非真实购买转化" |
| 25-44 岁用户占 70% | 实测 **75.84%** | 可用，建议直接写 75.84% |

> 这几处并非谁算错了，而是行业经验区间与本数据集的实际分布不同。任何对外材料中的数字都应能被追问到具体 SQL 那一步，因此本报告全部采用实跑值。
